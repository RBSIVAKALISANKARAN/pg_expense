Schema / SQL enhancement ideas

  • Add indexes for frequent transaction filters such as occurred_at, type, category_id and account_id.
  • Prefer aggregate reports from SQL for large datasets instead of loading every transaction into browser JavaScript.
  • Keep wallet transfers as paired transactions so source and destination movements remain auditable.
  • Consider a dedicated payment-method master only if the set becomes user-configurable; static payment semantics can remain validated choices.
  • Keep Travel Card and Change Cash as wallet/location types, while the account balance remains the source of truth for money held there.
